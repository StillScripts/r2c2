How it works

Write it once. Freeze it. Serve it everywhere.

  1. 01 · Write

    Edit the real page

    AI and people edit the actual HTML in the Loft, one element at a time. There is no block schema between what you write and what visitors get.

  2. 02 · Publish

    Freeze a version

    Publishing cleans the HTML, compiles its Tailwind in about 20 ms and saves an unchangeable version to R2. The edge picks it up within a minute.

  3. 03 · Serve

    Answer from the edge

    The domain picks the site, the cache returns the page, and the renderer only runs after a publish or when a cached copy expires.

The ideas it's built on

Generate when editing, not when visiting

AI writes pages in the Loft. Visitors get the frozen result, so every visitor and every search engine sees the same approved page.

HTML with holes

Live data like opening hours or stock lists comes from a few custom tags, such as <site-hours>, filled in at the edge.

Every publish is a version

Old versions stay in R2. Rolling back is pointing the page at an older file, with no rebuild.

No servers to run

One Worker, one bucket and one routing table serve every site. Cloudflare handles domains and certificates.

The Loft

A quiet place to get things done.

The Loft is where you shape your sites. Say what you want, see it, and publish when it's right. It's simple, clean and free of distraction, with every site, page, version and enquiry in one calm place.

Every publish is kept

Domains without the DNS headaches

Everything a site collects, in one inbox

Enquiries, bookings and orders arrive here, with where each visitor came from.

Model Context Protocol

planned

Run your website from the AI you already use.

Every R2C2 site gets an MCP server. Connect Claude, ChatGPT or any MCP client, and manage your site in the same conversation you use for the rest of your business. The AI drafts, shows you a private preview, and publishes only when you say so.

Drafts on a private link
Every draft gets an unlisted preview on your own domain. It expires, and search engines are told not to index it.
The same rules as the Loft
The AI gets the same permissions, checks and version history as the Loft, so anything it changes can be rolled back.
Publishing is your call
Publishing is its own step, marked as a change to the live site, so your assistant asks you before it happens.

Forms, bookings and payments

Static pages that still take enquiries, bookings and payments.

The interactive parts of a page are small tags like <site-form>, <site-booking> and <site-buy>. They send to /_api on the site's own domain, never straight to the database.

Form on the page POST /_api/forms/contact
→
Gateway Worker bot check · rate limit · site from domain · checks the fields · signs the request
→
Convex verifies the signature · internal functions only

Spam stops at the edge before it costs anything. The site always comes from the domain, so a request can't claim to be another business. Convex only accepts calls signed by the Worker, and checks every field again.

Architecture

The whole request path fits on one line.

Visitor any client domain
→
Cloudflare edge TLS per domain
→
Gateway domain → site
→
Workers Cache hit: done here
→
Renderer on a miss only
→
R2 live HTML file

Publishing runs the other way: the Loft writes a new version to R2, and the edge picks it up when its cached copy expires, within a minute. Convex holds the drafts and history; it is never in the path that serves a visitor.
